# 1단계 결과 · 기존 엔진의 독립 호출 검증

작성일: 2026-11-19
상태: 오프라인 연결 검증 완료. 실제 모델·HTTP 서버 연결은 미완료.

## 결론

기존 Streamlit 앱을 변경하지 않고 `graph.runtime.make_graph`를 별도 Python 프로세스에서 실행할 수 있다. 검색·LLM·날씨·상세 조회를 주입해 실제 그래프와 검증기를 통과했다. 새 프로젝트의 HTTP 어댑터를 개발할 수 있는 경계를 확인했다.

## 확인한 경로·의존성

- `rag/bm25.py`와 `rag/dense.py`의 기본 정제본·색인 경로는 원본 소스 위치 기준이다.
- `graph.runtime.open_checkpointer()`의 기본 채팅 DB는 상대 경로 `data/chat.sqlite`다. 웹앱 연결 시 반드시 별도 절대 경로를 전달해야 한다.
- `Trace`의 기본 실행 기록 경로도 원본 저장소다. 웹앱의 trace는 별도 저장 경로를 전달해야 한다. 이번 검증에서는 `Trace(save=False)`로 파일 기록을 끈다.
- 원본 환경에 uvicorn·httpx는 있고 FastAPI는 없다. 원본 환경을 변경하거나 의존성을 설치하지 않았다.
- 체크포인터를 포함한 그래프는 세션별 상태 관리가 필요하다. 여러 HTTP 요청에서 같은 세션이 동시에 수정되지 않도록 서버 계층에서 잠가야 한다.

## 선택한 연결 방식과 제한

이번 단계는 원본 인터프리터와 명시적 작업 디렉터리를 사용하는 프로세스 연결이다. 자식은 원본 runtime을 직접 가져오며 sys.path 변경, 소스 복사, 비밀·데이터 복사를 하지 않는다. API 서버의 Python 환경과 엔진 환경을 분리할 수 있는지 확인하는 임시 개발 방식이다.

실서비스가 요청마다 새 모델을 로딩하게 설계하지 않는다. 다음 연결 단계에서는 모델을 유지하는 단일 장기 실행 엔진 프로세스 또는 설치 가능한 엔진 패키지 중 하나를 결정한다. 현재 probe를 그대로 사용자 코스 생성 엔드포인트로 노출하지 않는다.

## 후속 개발 순서

1. 프런트엔드 구조 이전과 6종 캐릭터 명세·포즈 정리.
2. API 계약 확정. 세션·작업 ID, 되묻기·포기·코스 결과 타입, 실제 상태 이벤트를 정의.
3. 별도 환경에 FastAPI를 설치하고 가짜 엔진으로 HTTP·SSE·오류·중복 전송을 검증.
4. 엔진 장기 실행·색인 재사용·별도 체크포인트 경로를 구현.
5. 실제 모델·외부 API 연결 후 비용·지연·실패율과 브라우저 전체 흐름을 측정.

현재 웹앱은 여전히 디자인 체험 버전이며 실제 여행 생성이 연결됐다고 표시하지 않는다. 공개 배포나 실제 모델 호출은 이번 작업에 포함하지 않았다.
