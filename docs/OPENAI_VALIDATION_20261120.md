RateLimitError만으로 일시적 속도 제한인지 계정 사용 한도/결제 문제인지 구분할 수 없다. 실패 당시 원문 본문은 실행 기록에 남기지 않아 세부 사유를 확인하지 못했다. 새 오류 분류기는 향후 응답의 insufficient_quota 등 안전하게 분류할 수 있는 단서가 있을 때만 한도 초과로 표시한다.

기계 판독 요약과 원본 결과는 git 제외 `data/live-validation-openai-20261120/`에 있다. 실제 코스 생성·수정의 성공 증거로 사용하면 안 된다.

## 함께 수정한 것

1. LLM 호출 예외를 웹앱 어댑터에서 기록하고, 조건 해석기가 예외를 삼켜 ask_back으로 바꾸더라도 최종적으로 failed 이벤트를 반환한다.
2. 사용 한도·요청 속도 제한·인증·통신·요청 거절을 안전한 코드로 구분한다. 원문 오류·주소·키는 클라이언트에 전달하지 않는다.
3. 한 작업에서 제공자 오류가 발생하면 그래프의 후속 호출이 같은 제공자를 반복 호출하지 않도록 막는다. SDK 자체 재시도 설정과는 별개다.
4. 제공자 오류는 엔진 프로세스 통신 장애와 구분하여 불필요한 모델 재로딩을 막는다.
5. 프런트엔드에서 AI 서비스 오류에 맞는 안내를 표시한다. 오류를 조건 부족으로 오해하게 만들지 않는다.

원본 tour-planner의 코드나 비밀 파일은 변경하지 않았다.

## 남은 조건

OpenAI 계정의 사용 한도·결제 상태와 호출 제한을 확인해야 한다. 실제 상세 오류 본문이 없으므로 원인을 단정하지 않는다. 조건이 해소된 뒤 실제 코스 생성과 지정 칸 수정의 종단 검증을 다시 해야 한다. 현재 실제 API를 이용한 일정·지도·날씨·수정 결과 검증은 완료되지 않았다.

오류 구분 참고: [OpenAI 공식 Error codes 문서](https://developers.openai.com/api/docs/guides/error-codes/). 429에는 요청 속도 제한뿐 아니라 크레딧·프로젝트·조직의 지출/사용 한도 코드가 있어 상세 코드가 필요하다.
