# TripBuddy

**여행 친구 캐릭터와 대화하며 일정을 만들고, 원하는 장소만 바꿀 수 있는 모바일 우선 웹앱입니다.**

여행지와 날짜, 일수를 입력하면 일자별 코스를 제안합니다. 계획이 바뀌면 전체 일정을 다시 만드는 대신 “첫째 날 점심만 바꿔 줘”처럼 날짜와 슬롯을 지정해 수정할 수 있습니다. 현재는 로컬에서 실행하는 프로토타입입니다.

## 주요 기능

- **캐릭터와 여행 시작** · 여행 친구 6종 중 하나를 고르고 닉네임을 설정합니다. 설정은 브라우저에 저장됩니다.
- **대화로 조건 입력** · 지역과 일정을 폼이나 대화로 입력합니다. 날짜가 빠지면 기존 조건을 유지한 채 출발일을 되묻습니다.
- **일정 생성과 부분 수정** · 생성 진행 상황을 확인하고, 일정 카드나 대화에서 특정 날짜의 장소를 바꿉니다.
- **지도와 내보내기** · 날짜별 방문 순서를 지도에 직선으로 표시하고 일정을 Markdown으로 내려받습니다.
- **새로고침 후 이어보기** · 같은 탭에서 새로고침하면 서버에 남아 있는 대화, 결과, 진행 중인 작업을 복원합니다.

## 기술 구성

| 영역 | 기술과 역할 |
| --- | --- |
| 프런트엔드 | Next.js, React, TypeScript로 캐릭터 선택부터 대화, 일정 확인, 내보내기까지 구성 |
| API | FastAPI로 익명 세션, 작업 큐, SSE 진행 이벤트 제공 |
| 여행 엔진 | 기존 Tour Planner의 LangGraph 워크플로를 별도 Python 프로세스로 실행 |
| 지도 | Leaflet과 OpenStreetMap으로 방문 장소와 날짜별 동선 표시 |

### 구현에서 다룬 문제

- **장시간 작업의 진행 표시** · 여행 코스 생성은 작업 큐에서 처리하고, 엔진의 단계별 이벤트를 SSE로 전달합니다. 브라우저는 작업 ID로 진행 상황을 다시 조회할 수 있습니다.
- **기존 엔진과의 연결** · FastAPI와 여행 엔진을 서로 다른 Python 환경에서 실행합니다. API는 장기 실행 엔진 프로세스에 요청을 전달하며, 단일 작업 큐가 엔진 호출을 직렬화합니다.
- **부분 수정 검증** · 저장된 요청과 응답으로 실 API 호출 없이 생성·수정 사례를 재생합니다. 수정 대상 밖의 장소 ID, 빈 슬롯, 검증 규칙 위반을 검사하고 기존 이슈를 별도로 표시합니다.

## 로컬 실행

Node.js 20.9 이상과 Python 3.14 환경에서 확인했습니다. 엔진 코드와 의존성이 설치된 기존 `tour-planner` 프로젝트를 `trip-buddy`와 같은 상위 폴더에 준비한 뒤, 이 저장소 루트에서 실행합니다.

```sh
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.lock.txt
npm --prefix frontend ci
npm run dev
```

- [웹앱 · 포트 5174](http://127.0.0.1:5174)
- [API 문서 · 포트 8001](http://127.0.0.1:8001/docs)
- 엔진 경로가 다르면 `TRIPBUDDY_ENGINE_ROOT`와 `TRIPBUDDY_ENGINE_PYTHON`을 지정합니다.

기본 실행은 **체험 모드**입니다. 실제 LangGraph 흐름과 검증기를 사용하고 장소·날씨·모델 응답은 합성 데이터로 제공합니다. 캐릭터를 고른 뒤 “강릉 2일 여행”을 입력하고, 날짜를 물으면 미래 날짜를 입력해 생성과 부분 수정 흐름을 체험할 수 있습니다.

실제 모델 모드는 기존 엔진의 자격증명을 사용하며 API 비용이 발생할 수 있습니다. 사용 승인을 받은 환경에서 명시적으로 켭니다. 모델 제공자는 엔진 설정을 따르며 `TRIPBUDDY_PROVIDER=openai` 또는 `claude`로 지정할 수 있습니다.

```sh
TRIPBUDDY_MODE=live TRIPBUDDY_ALLOW_PAID=1 npm run dev
```

```sh
npm run typecheck       # 프런트엔드 타입 검사
npm run build           # 프런트엔드 프로덕션 빌드
npm run test:api        # 백엔드 테스트
npm run verify          # 엔진·API·타입 검사와 저장 사례 재생
npm run test:regression # 저장 사례만 재생
```

저장 사례 검증에는 Git에서 제외된 로컬 `data/regressions/`의 녹화본이 필요합니다. 기존 이슈까지 실패로 처리하려면 `npm run verify -- --strict-known`을 사용합니다. `npm run compare:distance`는 저장 사례를 이동 수단별 거리 기준 후보와 비교합니다.

## 현재 범위

- 세션과 작업 결과는 API 서버 메모리에 보관하며 서버를 재시작하면 새 세션이 필요합니다.
- 지도는 장소 간 직선 동선을 표시합니다. 지도 타일을 불러오려면 OpenStreetMap에 연결할 수 있어야 합니다.
- 체험 모드의 자유 입력은 규칙 기반으로 처리합니다. 실제 모델 검증은 위 강릉 사례 1건을 기준으로 기록했습니다.
