# TripBuddy · Character-driven travel web app

모바일 우선 여행 웹앱. Next.js/React/TypeScript 화면과 FastAPI 작업 API를 구성하고 기존 tour-planner 엔진을 별도 장기 실행 프로세스로 연결했습니다.

**기본 실행은 체험 모드입니다.** 실제 그래프·검증기를 거치지만 장소·날씨·LLM 응답은 합성 데이터입니다. 실제 여행에 사용할 수 없습니다. 실제 모델 검증은 별도 승인 범위로 진행합니다. 2026-11-19 Claude 요청은 API 오류, 2026-11-20 OpenAI 요청은 RateLimitError로 실패해 후속 수정은 실행하지 않았습니다. 공개 배포는 하지 않았습니다.

## 최신 실제 검증 · 2026-11-20

충전 후 gpt-5.4-mini로 강릉 2일 코스 생성과 첫째 날 점심 수정이 모두 성공했습니다. 코스 10칸, 최종 규칙 위반 0건, 다른 9칸의 장소 유지, Markdown 내보내기를 확인했습니다. 생성 58.4초·수정 6.03초이며 표본 1건입니다.

현재 실행 중인 로컬 서버는 실제 OpenAI 모드입니다. 새 요청을 보내면 API 비용이 발생합니다. 일반 `npm run dev`의 기본값은 계속 체험 모드입니다.

## 현재 기능

- 청년·중년·시니어 × 남성·여성 표현, 6종 캐릭터 선택과 기본/안내 포즈
- 닉네임·캐릭터의 브라우저 로컬 저장 및 변경
- 여행 조건 입력, 빠진 날짜 되묻기와 이어받기
- 서버 진행 이벤트, 일자별 일정, 지도 핀과 직선 동선
- 특정 날짜·슬롯의 장소 수정, 안내 문구, 정보 기준일
- 익명 대화 세션과 작업 소유 확인, 중복 요청 방지, 제한된 작업 큐
- 새로고침 후 같은 브라우저 탭의 세션·결과·실행 중 작업 복원
- Markdown 내보내기, 실패·재시도 및 네트워크 복구 경로

캐릭터는 현재 6종 선택형입니다. 피부색·헤어·의상 자유 조합은 미구현입니다. 실제 3D 모델이나 애니메이션이 아니라 생성한 일러스트를 상태별로 표시합니다.

## 체험 방법

1. 캐릭터를 선택하고 시작합니다.
2. 지역·출발일·일수를 고른 뒤 ‘선택한 조건으로 여행 시작하기’를 누릅니다.
3. 일정의 ‘이 장소 바꾸기’를 누르거나 `첫째 날 점심만 다른 식당으로 바꿔 줘`를 보냅니다.
4. 지도에서 날짜별 동선을 확인하고 Markdown을 내려받습니다.
5. 직접 `강릉 2일 여행`을 보내면 날짜를 되묻습니다. `2026-11-21 출발`처럼 답합니다. 실제 사용일보다 지난 날짜는 거절합니다.

체험 모드의 날짜·지역 해석은 제한된 규칙 기반입니다. 지원하는 명확한 입력은 `YYYY-MM-DD`, `M월 D일`, `내일`, `N일 여행`, `N박 N일`, 지역명입니다. 자유로운 자연어 해석과 취향 반영 품질은 실제 모델 연결 후 검증해야 합니다. 체험 데이터는 실제 장소명·실제 예보처럼 표시하지 않습니다.

## 실제 엔진 모드: 승인 후 실행

실제 모델 모드는 API 비용과 관광공사/날씨 조회를 발생시킬 수 있습니다. 사용자 승인 후 다음과 같이 명시적으로 켭니다. 제공자는 원본 config.LLM_PROVIDER를 따르며 TRIPBUDDY_PROVIDER=claude 또는 openai로 명시할 수 있습니다. 현재 원본 기본값은 openai입니다.

```sh
TRIPBUDDY_MODE=live TRIPBUDDY_ALLOW_PAID=1 npm run dev
```

원본 엔진이 관리하는 자격증명을 사용하고 복사하지 않습니다. 데이터는 원본 정제본을 읽고, 웹앱 색인·실행 기록·체크포인트는 이 프로젝트의 `data/`에 따로 생성합니다. 원본 모델 파일 캐시가 없으면 최초 다운로드·색인 생성이 필요할 수 있습니다.

## 비용 없는 일괄 회귀 검증

```sh
npm run verify
```

원본 엔진 단위 테스트 → API 테스트 → 프런트엔드 타입 검사 → 저장 사례 재생을 한 번에 실행합니다. 서버 재시작이나 새 여행 생성은 필요하지 않습니다. `TRIPBUDDY_ENGINE_ROOT`, `TRIPBUDDY_ENGINE_PYTHON`으로 기존 엔진 경로를 지정할 수 있습니다.

저장 사례만 빠르게 확인하려면 `npm run test:regression`을 실행합니다. 재생 중 네트워크·자식 프로세스를 차단하고 저장된 후보·초안·휴무 응답만 사용합니다. 현재 사례는 부산 ID/이름 오류, 부산 카페 칸 오류, 강릉 정상 생성, 강릉 점심 변경입니다.

- `PASS`: 기대한 칸 수·규칙·수정 범위 통과.
- `KNOWN_ISSUE`: 정확한 날짜·칸·장소 ID로 명시해 둔 기존 문제가 여전히 있음. 정상 통과가 아닙니다.
- `FAIL`: 새 위반, 장소 삭제, 빈 칸, 예상 밖 변경, 녹화 누락·변조 또는 실행 오류. 기본 명령이 실패 코드로 종료합니다.

기존 미해결 문제까지 실패로 처리하려면 `npm run verify -- --strict-known`을 사용합니다. 기본 명령이 종료 코드 0이어도 `KNOWN_ISSUE`가 있으면 전체 품질 합격을 의미하지 않습니다. 보고서는 `data/regressions/reports/latest.md`, `latest.json`에 생성됩니다.

새 문제는 엔진의 `scripts/capture_regression.py`로 SQLite를 읽기 전용으로 열어 검증 직전 체크포인트를 보존합니다. 사례명은 새 이름을 쓰며 기존 녹화는 덮어쓰지 않습니다. 예시(작업자가 실제 세션 ID를 지정):

```sh
../tour-planner/.venv/bin/python ../tour-planner/scripts/capture_regression.py --db data/chat.sqlite --thread SESSION_ID --suite data/regressions/suite --name new-case
```

수정 사례에는 `--mode edit --editable-slot '2026-11-21@점심'`처럼 허용한 칸을 명시합니다. 기존 문제 등록은 출력 확인 후 `--known-issue 'day_distance@2026-11-21'` 또는 `--known-issue 'unrequested_reason_change@2026-11-22@저녁@PLACE_ID'`로 한정합니다. 새로운 실패를 자동으로 기존 문제에 등록하지 않습니다.

사례는 체크섬으로 고정되고 TourAPI 내용이 포함되므로 git 제외 `data/`에만 보존합니다. 테스트는 현재 검색·새 모델 출력·최신 휴무·실제 UI를 확인하지 않습니다. 모델 입력·연결·화면을 변경한 경우 해당 범위의 제한된 실제 확인은 별도로 수행합니다.

## 지역·이동 수단별 거리 기준 비교

`npm run compare:distance`는 제안한 하루 직선거리 기준을 저장 사례에 가정해 비교합니다. 대중교통·자동차·도보별 추천 범위/최대치를 구분하며 보고서는 `data/regressions/policy-comparison/distance-comparison.md`와 `.json`에 저장됩니다.

이 명령은 현재 운영 기준, 코스, 요청의 이동 수단, 서버 상태를 바꾸지 않습니다. 기존 보정 코스를 그대로 새 하루 합 기준에 대입하며 새 기준으로 재배치하지 않습니다. 구간별 상한과 다른 검증 규칙은 별도이므로 거리 표의 추천 범위가 전체 코스 합격을 의미하지 않습니다. 정책 후보는 원본 `config.py`의 `PROPOSED_DAY_KM`, `PROPOSED_WALK_DAY_KM`에 별도로 보존합니다.

현재 실제 사례는 부산·강릉 저장 기록 4건(생성/수정 기록 중복 포함)뿐입니다. 서울·제주 기준은 경계값 단위 테스트만 수행했으며 실제 이동 시간이나 여행 적합성을 검증한 값이 아닙니다. 실제 적용 시에는 이동 수단 선택을 요청 파싱·작성·검증·안내에 일관되게 연결해야 합니다. 이동 수단을 캐릭터 외형으로 추정하지 않습니다.

## 저장·운영 제한

- 캐릭터 설정은 localStorage, 세션 인증 정보는 sessionStorage에 저장합니다. 토큰을 URL에 넣지 않습니다.
- API 세션·작업·결과는 서버 메모리에 있으며 서버 재시작 후 세션을 새로 만들어야 합니다. 계정과 클라우드 보관함이 아닙니다.
- 엔진은 단일 직렬 실행입니다. 대기열 최대 4개, 메모리 세션 100개, 작업 300개로 제한합니다. 초기 로컬 시제품의 제한이며 한도 도달 시 서버 재시작이 필요합니다.
- 엔진 장애 시 프로세스를 재시작합니다. 체험 체크포인트는 메모리 전용이라 장애 전 대화를 이어받지 못할 수 있습니다. 새 여행을 시작해 주세요.
- 실제 모드의 엔진 체크포인트 파일은 웹앱 세션과 별개이며 계정 인증·장기 보관 정책은 후속 단계입니다.
- 지도 타일은 OpenStreetMap 외부 서버에서 불러옵니다. 타일 연결이 실패해도 장소 카드와 좌표는 확인할 수 있습니다. 동선은 직선 연결이며 길찾기가 아닙니다.
- 공개 배포·여러 API 프로세스 운영·작업 영속화·자동 만료·운영 인증은 아직 미구현입니다.
